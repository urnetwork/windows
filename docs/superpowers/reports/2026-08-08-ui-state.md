# URnetwork Windows — UI state of record

2026-08-08, at `beta/custom-server` `256fd03`. Written as the reference an agent
reads before touching the UI, so nobody re-derives it or re-litigates a settled
decision. Everything here was verified by running the built app, not by reading
code — where something is unverified it says so.

## The one paragraph

The client is a **full-bleed pane application**. There are no cards, no page
padding gutter, no max-width content cap, and no floating islands. A destination
is 2–3 vertical panes that each stretch the full height of the content area and
touch the window edges, divided by 1px hairlines, each with its own ~40px header
strip and independent scroll. Every list row comes from a `kit::MakePane*` call
with a **fixed** `Height`. This is deliberate and owner-approved; it replaced a
card layout that three rounds of rebalancing could not make stop reading as a
phone app.

## How it got here (so nobody reverses it by accident)

Four owner verdicts, in order, each overriding what came before:

1. *"UI is a bright white when I click on menu"* → Mica removed, then the
   `NavigationViewDefaultPaneBackground` acrylic overridden. **Do not
   reintroduce a backdrop**: this app paints a full-bleed opaque surface, so a
   backdrop can only ever replace the brand colour with the wallpaper.
2. *"too much inspiration from mobile… a lot of empty space and how its placed"*
   → the design-foundations pass (icon rail, borders, glyphs).
3. *"the UI has barely even changed… things need to fit in a fill, go with
   Portmaster looks, less random sized modules"* → **the card model was deleted**,
   not restyled. This is the current model.
4. *"Connect page looks good, I like the new design we can build from there.
   Redesign the rest of the UI"* → the remaining four destinations rebuilt to
   match.

The authoritative design source is
`docs/superpowers/specs/2026-08-08-windows-redesign-spec.md`. **Its OWNER
RECONCILIATION preamble overrides its own body**; five owner decisions live
there. Override #5 is the pane model.

## Destinations (5, plus footer)

| Rail | Destination | Panes |
|---|---|---|
| primary | **Home** (renders as "Connect" — no `home` key exists) | Connect 330dip · Activity `*` · Client statistics 380dip |
| primary | **Network** | list (search + SDK buckets) · detail |
| primary | **Earnings** (Wallet + Leaderboard merged) | wallets rail · tabbed ledger · points rail |
| primary | **Account** | plan rail · uniform 44px row list · balance-codes table |
| footer | **Support** | still the card model — deliberately out of scope |
| footer | **Developer** | still the card model; **hidden unless Advanced Mode is on** |
| footer | **Settings** | General · Device · About, three equal stars |

`NavigationView` is `PaneDisplayMode="Auto"`: labels ≥1008epx, compact icons
641–1007, overlay ≤640. **The page-title header is cleared on every pane
destination** — a 60px display-face title above a pane layout is the one thing
that stops panes reaching the ceiling, and it was the single biggest "is this the
same app?" fix.

The **persistent bottom status strip** stays (owner override #4, against the
redesign spec's advice to remove it): dot + state, Network, Selected provider,
Data. It densifies to 8 fields in Advanced Mode.

## The vocabulary — use it, do not invent a second one

**Styles** (`App.xaml`): `UrPaneStyle`, `UrPaneHeaderStyle`/`Height`/`TitleStyle`,
`UrGroupHeaderStyle`/`Height`/`TextStyle`, `UrPaneRowStyle`,
`UrPaneRowButtonStyle`, `UrPaneRowHeight` (40), `UrPaneListRowHeight` (36),
`UrPaneRowTallHeight` (44), `UrPaneVRuleStyle`, `UrPaneSearchStyle`,
`UrPaneColumnTextStyle`, `UrPaneMetaStyle`, `UrRowTitleStyle`, `UrRowNoteStyle`,
`UrRowIconStyle`, `UrPaneActionPrimaryStyle` / `UrPaneActionSecondaryStyle`.

**Builders** (`UrComponents.h`): `MakePaneRow`, `MakePaneKeyValueRow`,
`MakePaneListRow`, `MakePaneListRowButton`, `MakePaneGroupHeader`,
`MakePaneTwoLineRow(Button)`, `MakePaneTableRow`, `MakePaneTableHeader`,
`MakePaneEmptyLine`, `MakePaneSearchRow`, plus `MakeStatusField`.

Row heights are **36 / 40 / 44** and nothing else. A list picks one and holds it.
Two-line rows trim their note, never wrap — that is the price of the fixed
height, and the fixed height is the whole model.

`rows::SetPaneMode(bool)` in `SettingsSheets` makes the older
`Card/Heading/Row/NavRow/Divider/Supporting` helpers emit pane vocabulary, which
is how large section builders converted without per-call edits.

## Type and colour

**Brand faces only.** ABC Gravity (Extended / Extra-Condensed) for page titles,
the wordmark and the hero. **PP Neue Montreal for card/pane section headers and
all body** — moving section headers off ABC Gravity is what fixed the "two
clashing heading styles" complaint. PP Neue Bit for the wordmark.
**Segoe UI Variable was explicitly rejected as a text face** (owner override #1);
Segoe **Fluent Icons** is used for glyphs only, which costs no assets.

Palette is `UrColors.h`, byte-matched to Android/iOS — **do not add tokens
casually**. Semantics now in force: blue `#638BFC` = action and selected;
green = protected; amber = warning/pending; red = danger; **pale lime `#EFF7BB` =
earnings / contribution / premium only**; neutral grey = disconnected.

Consequence already applied: the Connect button moved **off** lime onto blue,
because lime on a VPN control spent the earnings colour on the one screen with
no earnings. Its foreground is `#101010`, not white — white on `#638BFC` is
3.0:1, which passes for a 24sp display face and **fails** for a 14sp label.
**Open question the owner has not ruled on:** the Upgrade buttons on Account and
Earnings currently render blue; by the semantics above they are exactly where
lime belongs.

## Advanced Mode

Persisted in `%APPROOT%\app_prefs.json` via `Paths::AppPrefsFile()` (the SDK's
`LocalState` has no generic key/value in its C ABI, so a client-owned preference
has nowhere to live in it). Toggle lives in Settings › Advanced.

It is **standing state, not an event** — loaded in `SdkHost::Initialize()`,
replayed synchronously in `MainWindow`'s constructor, so nothing renders Normal
and gets corrected a frame later. This is the third feature in this project that
needed that shape; the mode-notice channel is the worked example.

Normal → Advanced changes: Developer destination appears · status strip 4 → 8
fields · pane C leads with the **Inspector** · contract ids expand to full and
become selectable · Activity rows become selectable and focusable.

**The connection inspector** (the Portmaster ask): selecting an Activity row
shows Host, Addresses, Protected, Reason, Packets, Bytes, Last decision, and the
`DestinationExit → Exit` join — Via exit, Flows to this destination, Exit tier,
Exit flows, Dial failures, Exit state, Probe age. Three verdicts, not two:
`blocked` / `tunnelled` / **`local`** (traffic a split rule sent around the
tunnel is allowed *and unprotected*, and filing that under "allowed" hides the
thing the pane exists to surface). Selection is keyed by **block-action id, never
index** — the feed rebuilds on every push.

## Strings

945 keys ship; ~250 are used. **No English literal may be added to the UI.**
Two sanctioned fallbacks, both "key id in source, English until the key lands,
self-heals when it does":

- `pages::Adv()` / `AdvW()` — 49 `adv_*` ids (Advanced Mode)
- `DeveloperPage`'s `Dev()` — 89 `dev_*` ids
- `SettingsPage`'s local `Missing()` — 2 (`advanced`, `about`)

Extract with `grep -ohE '"(dev|adv)_[a-z0-9_]+"' app/src/App/*.cpp | sort -u`.

**Genuinely missing from the store, for `urnetwork/localizations`:** `home`,
`help`, `diagnostics`, `security`, `region`, `city`, `vpn_and_privacy`, `stable`,
"Advanced Mode", "Not connected", "Your internet traffic is not protected",
`details`/`session`/`inspector`, and the per-connection field labels.

## Verification harness (read before writing your own)

`…/scratchpad/`: `uia.ps1` (UIA + capture), `w2.ps1`/`w3.ps1`/`w3click.ps1`
(sizing + clicking), `tour.ps1`, `density.ps1`.

Traps already paid for, each of which produced false evidence at least once:

- `FindWindow` from a PowerShell P/Invoke needs `CharSet=CharSet.Unicode`; the
  sandbox may also block enumeration entirely (retry with sandbox disabled).
- `SetForegroundWindow` alone loses to the foreground lock — three "captures"
  turned out to be photographs of a browser. Minimize/restore, then verify.
- A maximized window's rect origin here is `(-9, 38)`; raw image coordinates
  click 38px high.
- `PrintWindow` does not composite acrylic or backdrops — it is why the light
  pane survived a fix. Use `CopyFromScreen` on an **active** window for colour.
- On a locked session `CopyFromScreen` returns the lock screen; `PrintWindow` is
  then the only capture.
- PowerShell is case-insensitive: a `-H` parameter and an `$h` handle are the
  same variable, which silently produced wrong capture heights for a whole round.
- The app re-applies saved placement on activation — size the window **last**.
- Filter processes **by path**, never `Select -First 1`: several worktrees run
  identically-named processes with identical window classes and titles.
- `--preview-ui=<dest>` renders signed-in surfaces with no session;
  `URNETWORK_PREVIEW_SAMPLE=1` populates rows. **Judge maximized first (2578px
  here)** — every layout defect in this project passed at one width and failed at
  another.

## Known-open UI items

- **Settings is not dense** — 11 preference rows across three panes leaves ~65%
  of a maximized window empty. There is no more preference content in the
  product; merging to two panes is the cheap lever. Owner has not ruled.
- **Support and Developer still use the card model** — deliberately out of scope
  so far.
- Network's detail pane is short while "Best available" is selected (~7 rows);
  it fills to ~14 with a real location, unverified without a session.
- Accessibility is coded but **not exercised**: no Narrator run, no keyboard tab
  order pass, no high-contrast, no text scaling, only 125% DPI on one display.
- Account's balance-codes table has only ever been seen empty (no sample path).
- The Advanced inspector has only run against sample data — the exit join has
  not been seen against real `DestinationExit` rows.
